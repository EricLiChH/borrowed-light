# 三个毕业挑战与方向路线

主线完成后任选一个挑战；**不要同时开三个坑**。每个项目先复用本书的阶段门、离线测试和错误分类，再学习领域特有知识。

---

## 怎么选

不要按「哪个听起来酷」选，按**你现在最缺的能力**选：

| 挑战 | 主要练什么 | 什么时候该选它 |
|---|---|---|
| A. PNG 隐写 CLI | 字节切片、二进制格式、文件边界 | 你对「字节、指针、切片」还没有肌肉记忆 |
| B. mini-redis 子集 | TCP、task、channel、共享状态、优雅关闭 | 你想真正掌握异步服务，而不只是会用 Axum |
| C. 文字冒险状态机 | enum、模式匹配、领域建模、属性测试 | 你写得出服务，但设计不出干净的领域模型 |

三个挑战的共同要求：**离线可测**。如果你的方案必须联网或依赖手工点击才能验证，那它还没有达到本书的标准。

## 挑战 A：PNG 隐写 CLI

在 PNG 里藏文本：解析 chunk 结构，插入自定义 chunk，再读出来。

**练什么**：字节切片（`&[u8]`）、大端/小端、CRC 校验、文件错误处理、`Result` 在真实边界上的形状。

**最小产物**

```text
$ pngme encode in.png -o out.png -c ruSt "hello"
$ pngme decode out.png -c ruSt
hello
$ pngme print out.png          # 列出所有 chunk 与长度
```

**验收证据**

- 所有测试使用临时文件与内存字节，不依赖仓库里的示例图片；
- 损坏的 PNG（截断、CRC 错、长度越界）都有明确错误变体，而不是 `panic`；
- 退出码符合本书约定：0 成功、1 输入内容问题、2 命令用法问题。

**常见陷阱**：把长度字段当成 `usize` 直接用（它来自不可信输入，越界会让程序崩）；忘记 CRC 校验；用 `Vec<u8>` 到处 clone 而不是传 `&[u8]`。

**参考设计**：[PNGme](https://jrdngr.github.io/pngme_book/)（仅链接，题目自行重写）。

## 挑战 B：mini-redis 子集

只实现 `GET`/`SET` 和一个有界 manager channel。

**练什么**：TCP frame 解析、每个连接一个 task、独占共享状态、优雅关闭、背压。

**最小产物**

```text
$ cargo run --bin server
$ redis-cli -p 6379 set hello world
$ redis-cli -p 6379 get hello
world
```

**验收证据**

- 一个集成测试：启动服务器、开两条连接、交叉读写、关闭；
- 一个测试证明「队列满时发送者进入 Pending」而不是阻塞线程；
- Ctrl-C 时所有连接任务干净结束，没有半条响应。

**常见陷阱**：用 `Arc<Mutex<HashMap>>` 而不先问「能不能让一个 task 独占」；用无界 channel，把背压问题变成内存问题；`.await` 处没考虑取消安全（[检查表](../async/channels-cancellation.md#4-取消安全检查表)在异步章节）。

**起点**：[Tokio tutorial](https://tokio.rs/tokio/tutorial)。先做[mini-redis 迁移实验](../async/mini-redis-lab.md)，再动手写自己的。

## 挑战 C：文字冒险状态机

五个场景、可保存进度、状态迁移用属性测试覆盖。

**练什么**：`enum` 建模、模式匹配的穷尽性、所有权在状态迁移中的流动、序列化、确定性随机源。

**最小产物**

```text
$ adventure --save run.json
> go north
你在一间有回声的大厅里。出口：南、东。
> take lamp
拿到了灯。
> save
已保存到 run.json
```

**验收证据**

- 领域层不依赖终端：所有状态迁移都能用纯函数测试；
- 属性测试：任意操作序列都不会让游戏进入「无出口且未结束」的状态；
- 存档格式有版本号，旧存档读入时给出明确错误而不是静默失败。

**常见陷阱**：把 `String` 当状态到处传（该用 `enum`）；用 `RefCell` 绕开借用检查；随机数直接读系统（该注入种子，测试才能复现）。

**约束**：不引入 Web 框架。这一挑战要证明的是**领域模型可以独立测试**。

## 学新领域时，复用这套方法

三个挑战都用同一套流程，它对任何新领域都成立：

| 步骤 | 做什么 | 本书里对应 |
|---|---|---|
| 1. 找一手资料 | 官方文档 / 规范 / 参考实现，不看二手教程 | 各章的"参考设计"链接 |
| 2. 做最小可运行 | 先让一条路径跑通，再谈结构 | CLI 阶段的顺序基线 |
| 3. 找边界 | 输入边界、错误分类、并发点 | 领域错误类型 |
| 4. 写确定性测试 | 临时端口、临时文件、注入时钟 | `docs/adr/0011` |
| 5. 回头看分层 | 哪一层藏了复杂度，哪一层只是转发 | `docs/adr/0016` |

**第 5 步最容易被跳过，也最有价值。** 项目做完后花半小时画一遍依赖方向，你会发现自己上次犯的错——通常是「把复杂度放错了层」。

## 方向路线

| 方向 | 下一项先修 | 一手入口 |
|---|---|---|
| 后端 | 事务、认证、可观测性 | [Axum 文档](https://docs.rs/axum)、[SQLx 文档](https://docs.rs/sqlx) |
| CLI / DevTools | 流式 I/O、信号、发布 | [Command Line Applications in Rust](https://rust-cli.github.io/book/) |
| WebAssembly | 所有权边界、JS 互操作 | [Rust and WebAssembly](https://rustwasm.github.io/docs/book/) |
| 嵌入式 | `no_std`、内存映射、外设 | [Embedded Rust Book](https://docs.rust-embedded.org/book/) |
| 系统 / OS | unsafe 边界、布局、并发原语 | [Rustonomicon](https://doc.rust-lang.org/nomicon/) |

**路线表不是待办清单。** 先选一个真实问题，再补它要求的那一列知识——反过来做（先学完再找问题）几乎总会半途而废。
