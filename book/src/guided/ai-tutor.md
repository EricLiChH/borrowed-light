# 用 AI 助手当教练，而不是答案机

| 任务 | 概念 | 预计时间 | 项目产物 |
|---|---|---:|---|
| 配置学习伙伴 | 提问模式、提示词、验证 | 20 分钟 | 一套可复用的提示词 |

这本教材假定你手边有一个对话式 AI 助手（Kimi、ChatGPT、Claude 或本地模型都行）。它能显著加速学习，也能让你学得更慢——区别只在于你让它扮演什么角色。

## 一条规则

> 永远不要让助手在你思考之前给出完整代码。

看过答案的大脑会产生“我会了”的错觉，而肌肉记忆来自你自己写出的、编译过的、报错过的那几行。助手最有价值的时刻不是给出答案，而是在你卡住时问回你一个问题。

## 六种提问模式

复制下面的提示词，把方括号里的内容替换成你的情况。

### 1. 诊断模式：只解释，不修复

```text
我在学 Rust。下面是我遇到的完整报错和最小可复现代码。
请只做三件事：
1. 用一句话说明编译器认为发生了什么；
2. 指出我的哪个假设是错的；
3. 给我一个验证这个假设的小实验（不是修复后的代码）。
不要给出完整修复。
```

### 2. 苏格拉底模式：让我自己想出来

```text
我要实现 [目标]。我已经写到这里：[粘贴代码]。
请不要给我代码。每次只问我一个问题，从我可能想错的地方入手。
我回答后再决定下一个问题。最多问五个问题就停下来，让我自己动手。
```

### 3. 讲解模式：把决定讲透

```text
请解释 [概念]，按这个顺序：
1. 没有它的时候，什么样的问题无法表达，或者会被推迟到运行期；
2. 它引入的代价（分配、装箱、编译期约束、可读性）；
3. 一个用错它的例子，以及正确的替代写法；
4. 标准库或本项目里的真实用例。
不要超过 300 字。
```

### 4. 代码评审模式：按项目的 lint 标准

```text
这是我写的 Rust 代码：[粘贴代码]。
请按 clippy::pedantic 的口味评审，按严重程度排序，最多五条。
每条给出：问题、为什么在这个项目里是问题、最小修改方向。
不要重写整个函数。
```

### 5. 出题模式：检验而不是复习

```text
我刚学完 [章节]，请出五道判断或选择风格的题，考察边界情况而不是定义，
例如“这段代码能编译吗”“这个函数的复杂度来自哪里”。
先只出题，我回答后你再逐条点评，并指出我理由里的错误。
```

### 6. 调试陪练模式：先猜后验

```text
我的程序行为是 [现象]，我期望 [期望]。
请先列出三个最可能的原因，按可能性排序，并说明每个原因可以通过什么
最小实验来证实或排除。不要读我的代码，先只给假设。
```

## 助手的四种典型失败模式

| 失败模式 | 表现 | 你的对策 |
|---|---|---|
| 幻觉 API | 给出不存在的标准库方法或 crate | 要求它给出 `docs.rs` 链接或 `std` 路径；编译一次即可证伪 |
| 绕过借用检查 | 满屏 `clone()`、`Rc<RefCell<>>`、`'static` | 追问“如果不用 clone，所有权应该怎么走”；再跑 clippy |
| 过时写法 | 用 `#[async_trait]`、旧 edition 语法 | 告诉它工具链版本，要求用当前版本的原生写法 |
| 顺着你说 | 你提出错误方案它也说“对” | 反向提问：“这个方案在什么情况下会失败？” |

## 把教材交给助手

每次开始新一章时，先发这段开场白，让助手知道上下文：

```text
我在按 borrowed-light 这本教材学 Rust，当前在第 [章节]。
我的背景：以前学过 Rust 但忘了大半，现在要重新上手并深入。
工具链：Rust 1.99，edition 2024。
项目代码在 projects/ 下，练习在 exercises/ 下。
请按“教练”模式回答：优先给问题和方向，不要直接给完整实现；
涉及 API 时请给出可以在 cargo doc 里查到的路径。
```

## 每章的三次求助

学完一章之前，只在该求助的时候求助：

1. **卡住 15 分钟后**：用诊断模式，把完整报错贴全（不要只贴最后一行）。
2. **测试通过但心里没底时**：用代码评审模式，问“这段代码三个月后最容易在哪里出问题”。
3. **一章结束时**：用出题模式做闭卷检验，答错的地方写进你的学习日志。

真正需要记住的不是答案，而是你曾经错误预测过哪些行为。

## 把它接到命令行：§scripts/tutor.py§

上面的提示词是手动复制粘贴的。仓库里还有一个把它变成命令的脚本，用 Kimi 开放平台驱动：

§§§sh
cp .env.example .env        # 填入 KIMI_API_KEY（.env 已被忽略）
python3 scripts/tutor.py --check
§§§

§check§ 会验证密钥与端点，并列出可用模型：

§§§text
端点 OK：https://api.kimi.com/coding/v1
可用模型：kimi-for-coding, kimi-for-coding-highspeed, k3, k3-256k
§§§

四种用法：

§§§sh
# 1) 单次提问，带上正在读的章节作为上下文
python3 scripts/tutor.py ask --chapter ownership "为什么 move 之后原绑定不能再用？"

# 2) 交互式连续对话
python3 scripts/tutor.py chat --chapter result-option

# 3) 让它评审你的代码（对应「代码评审模式」）
python3 scripts/tutor.py review --code src/main.rs

# 4) 换一种模式：explain / quiz / debug
python3 scripts/tutor.py ask --mode quiz --chapter lifetimes-generics-closures "出题"
§§§

真实输出（§--chapter ownership§，教练模式）：

§§§text
因为移动后堆上的资源只归新绑定所有：若原绑定还能用且也负责释放，析构时同一资源就会
被释放两次。所以编译器在移动那一刻就把原绑定标记为失效——这是规则 1（一个值只有一个
所有者）加规则 2（离开作用域时释放）的直接推论，你看到的 E0382 就是它替你算这笔账的结果。
§§§

几点说明：

- **模式与本章的六种提问模式一一对应**：§coach§（默认，苏格拉底式）、§explain§、§review§、§quiz§、§debug§。
- **§--chapter§ 会把整章正文作为上下文发过去**，所以它的回答会和教材的术语、示例保持一致。
- **每次问答都会记到 §work/§**（已在 §.gitignore§ 里），可以回头翻自己卡在哪。
- 密钥只从 §.env§ 读取，脚本本身不含任何密钥；§scripts/check_secrets.py§ 会阻止密钥进入仓库。

> 如果 §--check§ 报 401：先确认 §KIMI_BASE_URL§。§sk-kimi-§ 前缀的密钥属于 Kimi Code，
> 端点是 §https://api.kimi.com/coding/v1§；指向 Moonshot 的端点会被判为无效认证。
