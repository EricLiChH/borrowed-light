# Rust 快速入门 Cookbook：实施计划 v1

> 日期：2026-08-15  
> 状态：已完成首轮访谈并确认，可进入样章垂直切片实施  
> 已确认读者：曾经尝试过 Rust、但因长期未使用而需要恢复熟练度的“回归学习者”。

## 1. 一句话产品定义

一本中文优先、项目牵引、可运行的 Rust 快速入门 Cookbook：读者不是按顺序背完语法，而是在“解释 → 预测 → 运行 → 故意弄坏 → 修复 → 迁移到项目”的循环中，形成对所有权、借用、生命周期、类型系统、错误处理和并发的可操作心智模型。

核心路径采用“诊断后分流”：已经记得的语法可以快速通过，遗忘或理解不牢的部分才进入讲解、图示和练习，避免回归学习者从 `Hello, World!` 开始线性重学。

同一批内容通过两个入口访问：“引导路径”负责系统学习，“配方索引”按任务、概念和编译错误支持日常查询，不重复维护正文。

## 2. 成功标准

读者完成核心路径后，应能：

1. 在 10 分钟内完成环境检查并运行第一个可修改示例。
2. 看懂 Cargo 项目结构，能独立运行、测试、格式化和检查一个 crate。
3. 不靠死记规则，能用图和编译器信息解释常见的 move、borrow、lifetime 错误。
4. 熟练使用 `struct`、`enum`、模式匹配、`Option`、`Result`、迭代器、trait 和泛型完成普通业务逻辑。
5. 完成一个可发布的 CLI 项目，再独立完成一个带持久化、测试和基本可观测性的异步 Web 服务。
6. 知道什么时候应查标准库/API 文档，而不是继续依赖教程。

建议的量化验收：

- 标准路径总计 30–40 小时：核心能力恢复 8–10 小时、CLI 实战 8–10 小时、Web/异步网络实战 14–20 小时；每阶段可独立验收。
- 学习时间中至少 60% 用于运行、修改、调试或测试代码。
- 每个陡峭概念至少有：1 个心智模型图、1 个执行/内存状态图、2 个对比例、1 个编译失败实验、3 个练习。
- 所有代码在锁定的 stable Rust 工具链上自动构建；故意失败的例子用 `compile_fail` 或等价测试验证。
- 每章结束都有可检查的产物，而不以“读完”为完成标准。

## 3. 从现有资源中借什么，不借什么

| 资源 | 最值得借鉴 | 本项目要补的缺口 |
|---|---|---|
| [The Rust Programming Language](https://doc.rust-lang.org/stable/book/) | 权威概念顺序、`minigrep` 综合项目、把编译错误当教材 | 篇幅长；核心路径需要压缩，并增加即时练习和图示 |
| [Rust by Example](https://doc.rust-lang.org/rust-by-example/) | 短、可运行、可编辑的示例；mdBook 可直连 Playground | 例子之间缺少连续项目和迁移练习 |
| [Rustlings](https://rustlings.rust-lang.org/) | 自动重跑、编译失败修复、提示、进度和参考解；支持社区习题集 | 解释较薄，需要和正文、图示、项目关卡一一对应 |
| [Comprehensive Rust](https://google.github.io/comprehensive-rust/) | 高密度课程结构、由浅入深的四日基础路径、专题分支 | 更像授课材料；自学时需要更多脚手架与反馈 |
| [100 Exercises to Learn Rust](https://rust-exercises.com/100-exercises/) | 小步测试驱动、每个概念紧跟练习、独立 runner | 默认读者会另一门语言；需要中文语境和更强的所有权可视化；其内容为 CC BY-NC，不能无条件复用 |
| [Brown 交互版 Rust Book](https://rust-book.cs.brown.edu/) / [Aquascope](https://cel.cs.brown.edu/aquascope/) | 测验、误解驱动的改写、编译期权限与运行期状态可视化 | 属于实验性教学工具；应准备静态图和简化解释作为稳定兜底 |
| [Rust语言圣经](https://course.rs/) / [配套练习](https://practice.course.rs/) | 中文表达、完整覆盖、中文读者常见疑问 | 目标不是再做一部百万字大全；该仓库声明 No License，只做竞品观察，不复制内容 |
| [Exercism Rust Track](https://exercism.org/tracks/rust) | 大量独立练习、测试驱动、解法比较 | 容易和正文脱节，应只选作扩展训练链接 |
| [Command Line Applications in Rust](https://rust-cli.github.io/book/) | CLI 是低依赖、反馈快、适合入门的项目载体 | 需要将语言概念和项目里程碑更紧地交织 |
| [PNGme](https://jrdngr.github.io/pngme_book/) | “给需求和测试、不给完整代码”的早期进阶项目设计 | 不负责教授语言基础，适合作为毕业挑战的设计参考 |
| [Tokio mini-redis 教程](https://tokio.rs/tokio/tutorial/setup) | 用真实协议串起 async、并发、channel、I/O | 官方明确要求已有 Rust 基础，只能放在核心路径之后 |
| [Zero to Production in Rust](https://www.zero2prod.com/) | 端到端后端工程、集成测试、可观测性和 CI/CD | 约 600 页且偏专业后端，适合作为进阶路径标杆而非快速入门主线 |

调研原则：以官方文档、项目自身网站/仓库和作者资料为事实来源；只吸收教学模式与公开 API 知识，所有正文、图、题和项目代码均原创，并维护来源与许可清单。

最终发布范围已确定为公开开源教程：在线静态网站免费阅读，练习和项目仓库可下载、本地运行并接受社区贡献。当前保持预发布状态，不创建远程仓库、不启用 Pages、不执行部署。原创正文与图示采用 CC BY 4.0，原创代码与练习采用 MIT OR Apache-2.0；第三方素材单独审计和标注。

语言采用中文主讲与中英术语对照：关键概念首次出现时附英文，代码、API 和编译器错误保留英文原文，再用中文拆解，以便读者检索官方资料和真实错误。

## 4. 已确认的交互式学习架构

采用“浏览器轻交互 + 本地深交互”的双轨方案：

```mermaid
flowchart LR
    A["短讲解与图示"] --> B["先预测结果"]
    B --> C["浏览器中运行/改写"]
    C --> D["本地编译失败实验"]
    D --> E["自动测试与分层提示"]
    E --> F["项目检查点"]
    F --> G["复盘卡与迁移题"]
    G --> A
```

### 第一层：零门槛阅读与试跑

- 用 mdBook 组织中文正文、导航和搜索。
- 简短、无外部依赖的代码块可编辑并发送到 Rust Playground 运行。
- 图示优先使用可版本控制的 Mermaid/SVG；复杂所有权案例链接到 Aquascope，同时保留静态逐帧图。
- 困难概念统一采用三视图：行号高亮代码、逐步静态状态图、精选交互演示；三者必须描述同一段代码和同一组状态。
- 图必须有文字说明、符号/标签冗余，不能依赖颜色传达唯一信息；装饰性图片不计入教学图示。
- 每个概念先要求读者预测“能否编译、输出是什么、谁拥有值”，再允许运行。
- 每个学习单元携带任务、概念、错误码、先修知识和项目阶段元数据，同时生成引导路径与配方索引导航。

### 第二层：本地练习与真实反馈

- 提供一个 Cargo workspace；每章有 `starter`、测试、分层提示和完成条件。
- 使用 Rustlings 社区习题集机制：它已有 watch、提示、状态、重置和解答流程，第一版不自研 runner。
- 练习分五类：补全、修复编译错误、补测试、重构为惯用 Rust、扩展项目功能。
- 解答分三层开放：方向提示 → 关键 API → 惯用解与取舍，避免一键剧透。
- 自动练习与项目测试不访问公网：使用本地临时 HTTP 服务、可控时间和临时 SQLite 数据库。
- 学习进度只保存在本机：Rustlings 状态 + 诊断生成的个人路线 + 项目检查点测试；第一版无账户、云同步或排行榜。

### 暂不建议 v1 自研完整网页 IDE

纯网页沙箱的安装体验最好，但依赖运行隔离、资源限制、依赖缓存、账户/进度同步和安全维护。v1 先验证内容与学习闭环；若大量目标读者不能安装本地工具链，再将网页执行环境列为 v2。

课程技术底座已确定为 mdBook + Rustlings 社区习题集 + 单仓库 Cargo workspace。当前开发机 Rust 为 1.86，而调研时 mdBook 0.5.4 的官方安装文档要求至少 Rust 1.88；实现阶段需先升级或固定一组兼容版本，并在 CI 中验证。

## 5. 内容地图

### 0. 十分钟起跑

- 安装/检查 stable 工具链，认识 `rustup`、`rustc`、Cargo、`rust-analyzer`。
- `cargo new`、`cargo run`、`cargo test`、`cargo check`。
- 第一课就读一条编译器错误：错误信息是配对教练，不是失败通知。
- 用一组短诊断题检查语法、类型、所有权、错误处理和 Cargo 熟练度，并生成“快速通过 / 需要复习”的个人路线。
- 产物：一个带测试的“单位换算器”。

### 1. 先写出有用程序

- 变量、可变性、表达式、函数、控制流。
- `String` 与 `&str` 先从使用场景认识，不立即展开全部内存规则。
- `struct`、`enum`、模式匹配、`Option`、`Result`。
- `Vec`、`HashMap`、迭代器的常用配方。
- 产物：内存中的监测目标与检查结果模型。

### 2. 跨过第一面墙：所有权与借用

- 栈、堆、值、位置、作用域、drop。
- `Copy` 与 move；借用与可变借用；切片。
- 用“某一时刻允许哪些操作”的权限模型解释借用检查，而不是只背三条规则。
- 每个错误展示：代码 → 读者预测 → 编译器信息 → 状态图 → 最小修复 → 设计更好的修复。
- 生命周期先解释“引用之间的关系”，只教能解决当前函数/结构体问题的标注。
- 产物：把监测目标与检查结果重构成无多余 clone、边界清晰的 API。

### 3. 写出惯用且可维护的 Rust

- 模块、crate、可见性与 Cargo workspace。
- trait、泛型、trait bounds、静态/动态分发的入门边界。
- 闭包、迭代器、常见转换；何时普通循环更清楚。
- 错误设计：传播、上下文、自定义错误；库与应用的差异。
- 用 trait 定义存储边界，并用内存实现完成快速测试；暂不引入数据库。
- 单元测试、集成测试、文档测试；`rustfmt`、Clippy。
- 产物：可安装、带帮助信息和集成测试的 CLI。

### 4. 和现实世界接上

- 文件、路径、stdin/stdout/stderr、环境变量。
- Serde 与 JSON/TOML；依赖和 feature 的最小知识。
- 日志与配置；不在入门路径中过早堆框架。
- 主项目：网站健康监测器；先完成网址管理、单次同步检查、配置与结果输出，再进入异步阶段。

### 5. 并发与异步，不跳过地基（必修阶段）

- 线程、消息传递、共享状态、`Send`/`Sync` 的直觉。
- `async fn`、`.await`、task、channel；为什么 future 是惰性的。
- 必修异步运行时统一使用 Tokio，不在核心路径横向比较多个 runtime。
- 使用可复用的 reqwest Client，将同步检查升级为并发任务；显式实现超时、有限重试、退避、错误分类和 Semaphore 限流，再阅读/改造 mini-redis 的一小段，而不是从零实现 Redis。
- 产物：带并发限制、超时、重试、错误汇总和测试的网站健康监测器 CLI。

### 6. Web 服务实战（必修阶段）

- 使用 Axum 构建小型 HTTP API，串起 Tokio runtime、路由、请求提取、共享状态和结构化错误。
- 依次用 SQLite + SQLx 替换内存存储，再加入配置、日志/追踪、优雅关闭和集成测试。
- 明确区分语言机制、异步运行时和 Web 框架，避免把框架魔法当作 Rust 本身。
- 产物：可本地运行、可测试、带 API 示例和最小部署说明的网站健康监测服务。
- PostgreSQL 与 Docker 只作为部署扩展，不阻塞标准路径。

### 7. 毕业项目与分支路线

- 核心毕业项目：真实可用、可安装、带文档和 CI 的网站健康监测器 CLI。
- 必修应用项目：将同一项目升级为受控并发网络客户端和小型 HTTP API。
- 可选项目：PNG 隐写 CLI（字节/协议）、mini-redis 子集（异步网络加深）、文字冒险/小游戏（状态建模）。
- 后续路线图：后端、CLI/DevTools、嵌入式、WebAssembly、系统/OS；每条只给先修知识和精选一手资源，不扩写成第二本大全。

## 6. 每个“配方”的固定结构（候选术语）

1. **任务**：今天要让什么工作起来，预计 5–20 分钟。
2. **先预测**：在运行前判断编译/输出/所有权变化。
3. **最小可运行例**：只引入一个新变量。
4. **看见不可见状态**：内存、权限、类型或任务时间线图。
5. **故意弄坏**：触发一条有教学价值的编译错误或失败测试。
6. **修复并解释**：先最小修复，再给惯用设计与取舍。
7. **挑战**：补全、修 bug、重构或扩展；自动验证。
8. **迁移到项目**：把刚学的能力用于连续项目。
9. **带走一张卡**：何时用、常见坑、下一次该查哪里。

“配方”“概念实验”“项目检查点”等词尚未成为正式项目术语；待访谈确认后再写入 `CONTEXT.md`。

## 7. 制作阶段与里程碑

### 阶段 A：需求收敛与资源审计

- 逐题确认目标读者、时间承诺、主项目领域、交互载体、发布方式和许可边界。
- 建立资源矩阵：覆盖范围、教学方法、更新状态、许可、可借鉴点、已知误区。
- 产物：目标读者画像、学习结果、正式目录、`CONTEXT.md`；必要时为平台选择写 ADR。

### 阶段 B：做一条端到端样章

- 制作一个预计 60–90 分钟完成的“move → borrow → mutable borrow”样章垂直切片。
- 同时交付入门诊断、正文、三视图图示、浏览器示例、Rustlings 失败练习、测试、分层提示、解答和网站健康监测器的领域模型检查点。
- 找 3–5 位目标读者试学，记录卡住位置、首次成功时间、提示使用率和错误答案。
- 通过条件：读者不是只把题做对，而是能解释一个未见过的近似案例。

样章验收清单：

1. 诊断题能够让熟悉内容的回归学习者跳过基础说明。
2. 至少包含一个 move、一个不可变借用和一个可变借用的编译失败实验。
3. 每个实验的代码、静态状态图和交互演示描述相同状态。
4. 浏览器示例能独立运行；本地练习能自动重跑、提示和判定完成。
5. 项目检查点产出 `MonitorTarget`、`CheckResult` 等最小领域类型，并有测试保护。
6. 全部示例、故意失败示例、链接和图示引用通过本地验证。
7. 完成后能回答一个未在正文出现的所有权变式题。

### 阶段 C：核心能力与 CLI 路径

- 按“能完成项目所需的最短依赖顺序”写作，不按语言参考手册顺序铺开。
- 每完成一章就运行代码、链接、格式、拼写和术语一致性检查。
- 每 3–4 章安排一次项目检查点和一次累计复习。

### 阶段 D：Web/异步网络路径与工程化

- 完成 CLI 主项目、异步网络客户端和 Web API，并提供 2–3 个可选毕业题。
- 加入安装、调试、测试、文档、发布和最小 CI。
- 对 Windows、macOS、Linux 的命令差异提供可验证说明。

### 阶段 E：验证与发布

- 内容 QA：概念准确、例子单一变量、错误信息与当前工具链一致。
- 图示 QA：代码行号、状态变化和文字说明一致；灰度与无交互环境下仍可理解。
- 代码 QA：build/test/fmt/clippy/doc/compile-fail 全自动。
- 网络 QA：CI 离线运行，不真实等待，不依赖共享数据库；公网检查仅为可选手动演示。
- 教学 QA：新手可完成、提示有梯度、图与代码状态一致。
- 先在本地完成与未来 CI 相同的构建、测试和链接检查，保持“可发布、未发布”。
- 获得明确发布授权后，再创建远程仓库，使用 GitHub Actions 发布 mdBook 到 GitHub Pages，并在版本标签生成离线练习包。
- 公开前提供贡献指南、行为准则、来源/许可清单，并记录对应 Rust edition/MSRV 和最后验证日期。

## 9. 主要风险与应对

| 风险 | 应对 |
|---|---|
| “快速入门”变成删掉解释的速查表 | 只压缩非关键语法；所有权、错误处理和 async 保留多模型、多反例 |
| 交互功能喧宾夺主 | 先用现有 Playground/Rustlings 验证教学，再决定是否自研平台 |
| 账户与进度服务扩大维护范围 | 第一版只记录本地进度，不收集学习数据 |
| 练习能蒙对但不能迁移 | 加预测题、解释题、变式题和项目改动；不只判断最终输出 |
| 图示简化过度造成错误心智模型 | 明确图的抽象边界；与可运行代码/编译器结果成对验证 |
| 图、代码和工具演示发生漂移 | 三视图共享同一示例来源，并在审阅清单中逐步核对状态 |
| 示例随 Rust/依赖升级失效 | 锁工具链与依赖，CI 定期验证，同时标注最后验证日期 |
| 公网与时间造成测试偶发失败 | 本地临时服务、可控时间、临时 SQLite；CI 禁止真实公网依赖 |
| 资源许可不清 | 只引用链接和教学观察；复用前逐项审计许可并保留署名 |
| 内容范围膨胀 | 核心路径只保留毕业项目必需知识；专业方向全部移到分支路线 |

## 10. 已完成的首轮决策树

以下决策已按依赖顺序逐项确认：

1. **目标读者（已确认）**：曾经尝试过 Rust、但长期未使用的回归学习者。
2. **完成定义（已确认）**：先恢复核心能力并完成 CLI，再完成 Web/异步网络必修阶段。
3. **时间预算（已确认）**：标准路径总计 30–40 小时，可按约四周推进，但不绑定固定日历。
4. **主项目领域（已确认）**：网站健康监测器，从 CLI 演进为异步 Web 服务。
5. **交互入口（已确认）**：浏览器轻交互 + 本地 IDE 深交互；第一版不自研完整网页 IDE。
6. **内容形态（已确认）**：同一内容同时提供线性引导路径与任务/概念/错误配方索引。
7. **发布范围（已确认）**：公开开源教程；在线免费阅读，仓库可下载并接受社区贡献。
8. **语言策略（已确认）**：中文正文 + 中英关键术语对照；代码、API 和错误信息保持英文。

## 11. 已确认的第一项决策

核心读者是“回归学习者”，而不是完全零基础读者。核心路径提供入门诊断与跳过机制；必要的基础知识保留为可检索补充，不强迫所有读者从头重学。

## 12. 已确认的第二项决策

Web/异步网络属于最终完成目标，但采用分阶段交付：核心能力恢复 → CLI 实战 → 异步网络 → Web 服务。读者可以在每个阶段获得独立成果，“快速上手”不以牺牲最终应用能力为代价。

## 13. 已确认的第三项决策

标准路径的总投入为 30–40 小时：核心能力恢复 8–10 小时、CLI 实战 8–10 小时、Web/异步网络实战 14–20 小时。四周是推荐节奏而非硬性课程周期。

## 14. 已确认的第四项决策

用网站健康监测器贯穿全书：从领域类型与同步 CLI 开始，逐步加入文件配置、异步并发、超时、重试、持久化、HTTP API、日志和集成测试。其他项目只作为迁移练习或可选毕业挑战。

## 15. 已确认的第五项决策

采用双轨交互：浏览器负责阅读、图示、预测题和轻量运行，本地 IDE 负责自动练习、编译反馈、测试、进度与完整项目。第一版不自研完整网页 IDE。

## 16. 已确认的第六项决策

同一批学习单元同时提供“引导路径”和“配方索引”。前者按知识依赖与项目演进组织，后者按任务、概念和编译错误检索；不复制正文，以免两个入口产生内容漂移。

## 17. 已确认的第七项决策

项目作为公开开源教程发布：提供在线静态网站和可下载的本地练习仓库，并允许社区按许可证贡献。由此必须把来源审计、可复现构建、跨平台说明和贡献规范纳入第一版质量要求。

## 18. 已确认的第八项决策

采用中文主讲与中英术语对照。关键概念首次出现时附英文；代码、API 和编译器错误保持英文原文，再提供中文拆解，从而兼顾中文理解与英文官方资料检索。

## 19. 已确认的第九项决策

原创正文与图示采用 CC BY 4.0，原创代码与练习采用 MIT OR Apache-2.0 双许可。第三方材料逐项记录来源与许可；不明确或不兼容的内容只做链接和原创评述，不复制。

## 20. 已确认的第十项决策

第一版课程底座为 mdBook + Rustlings 社区习题集 + 单仓库 Cargo workspace。正文、习题和网站健康监测器共同版本化；第一版不自研练习运行器。

## 21. 已确认的第十一项决策

必修应用栈使用 Tokio + Axum。Tokio 承担异步运行时、任务、定时器、网络和同步原语，Axum 承担 HTTP 路由、请求提取、响应与中间件；其他运行时和框架不进入主线比较。

## 22. 已确认的第十二项决策

持久化采用两阶段设计：先以内存实现学习领域接口、共享状态和测试，再在 Web 阶段使用 SQLite + SQLx 教授迁移、连接池和查询。PostgreSQL 与 Docker 只作为部署扩展。

## 23. 已确认的第十三项决策

HTTP 客户端使用一个可复用的 reqwest Client；课程显式实现检查调度层中的并发限制、总超时、有限重试、退避和错误分类，不在第一版用黑盒中间件隐藏这些机制。

## 24. 已确认的第十四项决策

所有自动化测试保持离线和确定：本地临时 HTTP 服务模拟网络，可控时间验证超时/重试，临时 SQLite 隔离数据库。真实网站只用于明确标记的手动演示。

## 25. 已确认的第十五项决策

所有权、借用、生命周期与异步等困难概念采用三视图图示：行号对齐的代码、逐步静态状态图和精选交互演示。所有图附文字说明且不依赖颜色传达唯一信息。

## 26. 已确认的第十六项决策

第一版学习进度只保存在本地：Rustlings 记录练习状态，诊断生成个人路线，项目测试验证检查点。项目不提供账户、云同步或排行榜。

## 27. 已确认的第十七项决策

最终托管使用 GitHub Pages + GitHub Actions，并为版本标签生成离线练习包；当前保持预发布状态，不创建远程仓库、不启用 Pages、不部署。公开上线必须重新获得明确授权。

## 28. 已确认的第十八项决策

首个制作里程碑是一个预计 60–90 分钟完成的样章垂直切片，覆盖入门诊断、move/borrow/mutable borrow、三视图图示、浏览器示例、Rustlings 练习与分层提示，以及网站健康监测器的第一个领域模型检查点。通过小范围试学验证后，再批量扩展全书。

## 29. 样章实施顺序

1. 固定兼容的 Rust、mdBook 与 Rustlings 版本，并记录 MSRV。
2. 建立单仓库 Cargo workspace、mdBook 和 Rustlings 社区习题骨架。
3. 先写诊断题与最终迁移题，明确样章的进入和退出能力。
4. 建立网站健康监测器的最小领域类型与测试。
5. 按 move → immutable borrow → mutable borrow 编写三个概念实验。
6. 为三个实验制作行号对齐代码、静态状态图和精选交互演示。
7. 加入 Rustlings 修错练习、三层提示、惯用解和项目检查点。
8. 运行正文代码、compile-fail、workspace 测试、格式、Clippy 与链接检查。
9. 邀请 3–5 位回归学习者试学，按证据调整节奏、图示和提示。
10. 样章达标后冻结配方模板，再进入核心路径批量制作。
